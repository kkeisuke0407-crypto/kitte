# 月次申込数バッジ

2026-11-03、ユーザーがC案（赤い丸）と文字拡大、月替わりの更新を指定。

## 表示と更新箇所

- `tools/data/monthly-award.json` の `companyId` と `period`（YYYY-MM）が生成元。
- 現在はウリエル、`2026-10`。表示は「2026年10月／申込数／No.1」。
- `tools/build-top.cjs` が年月を日本語化し、比較TOP・地域版・古い切手版へ反映する。
- デザインはC案の赤い丸。元の順位帯、高さ30px、中央の数字、赤字・青字・マイクロコピー・CTAを維持。
- No.1の文字はPC21px、通常スマホ15.5px、320px幅では13.5px（内側の白線と文字の横圧縮を外し、赤い円を広く使う）。丸の直径は64px、46px、40pxとし、画面端・中央の数字・ロゴに重ならないよう調整。

## 月替わりの実行設定

- Codexのこのチャットに月次処理を登録済み。名前「切手LPの月次申込数バッジ更新」、ID `lp`、毎月1日9:00（日本時間）。
- ユーザー回答により、前月分を表示する。2026年12月の更新対象は2026年11月。
- 対象月のASP実申込数または対象月がASP確認済みの資料を確認してから更新する。GA4のクリック・MCVは申込数の代わりに使用しない。
- 根拠を確認できない月は年月だけ先へ進めず、確認済みの表示を維持して必要情報を知らせる。
- ASPへの問い合わせ送信、広告キャンペーン・配信設定の変更は行わない。

## 反映手順

1. 最新のリモート、未コミット変更、公開元を確認。
2. 対象月の根拠を確認し、専用ブランチで `period` を更新。
3. `npm run build`、`node tools/audit.cjs`、差分チェックとスマホ・PC表示を確認。
4. ソースブランチへ統合。既存の `codex/pages` へ `tools/build-pages.cjs` でルートと `/kitte-kaitori/` の両方を生成して公開。
5. 本番の年月、表示、配信ファイルとの一致を確認して結果を記録。

2026年10月の表示は、既存のASP確認済みというユーザー指示を引き継ぐ。新しい月の実績確認は別に行う。
