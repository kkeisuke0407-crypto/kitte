## 方針と参照
以前のソウガクLPではGA4プロパティ`557942591`に、`lp_cta_view` / `lp_section_view` / `lp_scroll` / `lp_active_read` / `lp_faq_open` / `sougaku_mcv` が記録されていた。今回の切手買取では別プロパティ／別広告アカウントとして管理する。ソウガク独自Cloudflare Worker計測はWorker/D1のデプロイが未完了だったため、既設済みとは扱わない。

## LPイベント（`window.dataLayer`）
| event | 発火条件 | 備考 |
|---|---|---|
| `lp_page_view` | ページ表示 | `lp_id`, `lp_path`, `measurement_mode` |
| `lp_scroll` | 25/50/75/90/100%到達 | `scroll_percent`、各マーク1ページにつき1回 |
| `lp_section_view` | ID付き見出し/セクション表示 | `section_id`、各セクション1回 |
| `lp_cta_view` | `a[data-place]`が50%以上表示 | `cta_place`, `cta_company`, `cta_pending` |
| `lp_active_read` | アクティブ閲覧30/60/120秒 | `active_seconds` |
| `lp_faq_open` | FAQの`details`開封 | `faq_label` |
| `lp_finder_start` | 診断の初回操作 | 診断回答の値は送らない |
| `lp_finder_complete` | 診断の実行 | 診断回答の値は送らない |
| `cta_click` | 任意の`a[data-place]`クリック | 内部リンクも含む。広告成果ではない |
| `kitte_mcv` | **成果リンク`a[data-aff]`から、ASP等の他ドメインへ有効な外部遷移をクリック** | `cta_company`, `cta_place`, `conversion_stage=affiliate_outbound`, `cta_pending=false` |

**MCV除外**：未設定プレースホルダ、`is-pending`内部遷移、ランキング内の単なる詳細ページリンク、福ちゃんの未提携ページ内リンクをMCV扱いしない。`kitte_mcv`は外部公式サイトへの遷移であり、広告主サイトでの申込完了を保証しない。

## セットアップ手順（接続権限が得られた後）
1. ボスアカウントMCC `820-007-4047`で「切手買取」子アカウントを新規作成。通貨`JPY`、時間帯`Asia/Tokyo`、管理権限/請求情報を確定。Google広告キャンペーンの作成や配信開始はまだ行わない。
2. GA4に切手買取専用のプロパティ`切手買取LP`（日本/JST/JPY）とWebデータストリーム（`kitte.navolio.net`の正しいLP URL）を作成。GTMコンテナも案件用に作成し、測定ID/コンテナIDを記録。**ソウガクのGA4測定IDを使い回さない**。
3. GTMを7ページの`<head>`へ追加。GA4設定タグを全ページ発火、上記dataLayer eventのカスタムイベントに個別のGA4イベントタグを設定。タグには`lp_id`, `measurement_mode`, `cta_company`, `cta_place`, `scroll_percent`, `section_id`, `active_seconds`など必要なパラメータだけ渡す。GA4側に必要なイベントスコープのカスタムディメンションを登録。
4. MCVのGoogle Adsコンバージョンアクション名は`切手_MCV_公式遷移`とし、イベント`kitte_mcv`のうち`cta_pending=false`, `measurement_mode=normal`かつ外部ASPリンクのみで発火。**当面Secondary（入札最適化対象外）**、カウントは「1回」（ユーザーの運用状況で確定）。手動CPCのためMCVだけを成果申込と誤認して学習させない。GA4にも同じイベントを送るがGoogle広告へ二重インポートしない。
5. オフラインCVアクション名`切手_申込承認_オフライン`。初期はPrimaryの実成果として別アクション。登録にあたってはASP報告に`GCLID/GBRAID/WBRAID`または許諾された`subid`/クリックIDが成果単位で返るか確認。返らなければ**広告クリックと承認申込を連結できない**。ASP URLに独自パラメータを無断付加しない。取り込む際はconversion_name、conversion_time（JST表記を正規化）、価値、重複除外ID、成果状態、広告クリック識別子を合わせ、テスト1件を照合し、本番化する。
6. GCLIDの自動タグ付けを確認、必要なら広告側のGoogleタグで広告クリックの紐づけを維持。ASPが明示許可する場合だけ`subid`へ識別子を渡す。クリックと申込の突合ができていない期間は、オフラインCV「稼働済み」と報告しない。
7. GTM PreviewとGA4 DebugViewで7ページ・ウリエルの本当のASPリンク・保留中の内部リンク・FAQ・スクロール・診断を確認。内部アクセスは`measurement_mode=debug`でテストし、実計測ではフィルタ除外または内部トラフィック定義を行う。タグのテストイベントと本番イベントを区別。
8. プライバシーポリシーの実運用サービス名・Cookie・広告効果測定・第三者へのデータ送信を実装状態に合わせて再確認する。

## 技術的留意点
- HTMLは比較TOP、ウリエル詳細、バイセル詳細、福ちゃん詳細、調査概要、運営者、プライバシーの7ページ。共通`kitte.js`を読むため、LPイベントは全ページに適用される。
- ソウガク型の**Cloudflare Worker/D1による独自クリック座標・rage/dead計測**は切手買取に未導入。今回の追加はまずGA4/GTMに渡せるブラウザのdataLayerイベント基盤であり、自前ヒートマップ完成とは異なる。
- 現状のLPでは成果リンク `__URIEL_AFF_LINK__` `__BUYSELL_AFF_LINK__` が未設定。外部成果リンクへの実際のクリックが存在しなければ、MCVは0件になるのが正しい動作。
- 「MCVクリック」は実申込でも承認成果でもない。コンバージョン単価を扱う際は必ずアクション名と成立条件を併記する。
- ユーザーの許可は**計測実装と広告アカウント新規作成**まで。キャンペーン入稿/広告配信は未承認。
